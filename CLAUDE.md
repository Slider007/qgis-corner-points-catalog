# Плагин QGIS «Угловые точки и ведомость координат»

Устройство и возможности — в `README.md`. Общие правила модулей компании — в
`~/Projects/QGIS/CLAUDE.md`.

## Как выпускать версию

1. `tests/run_tests.sh` на 3.44 и 3.40 — все проверки должны пройти.
2. Поднять `version=` и дописать `changelog=` в `corner_points_catalog/metadata.txt`.
3. После подтверждения — коммит и пуш, затем релиз с архивом:
   `gh release create vX.Y.Z "$(./build_zip.sh)" --title X.Y.Z --notes "…"`.
4. Дальнейшие шаги — в локальном `CLAUDE.local.md`.

## Устройство

- `plugin.py` — кнопка: активный точечный слой, выделение, поле номера (иначе
  `QInputDialog`), запуск алгоритма в фоне (`QgsProcessingAlgRunnerTask`), по
  окончании — слой в проект, заголовки (псевдонимы), `iface.showAttributeTable`.
- `processing/table_algorithm.py` — алгоритм `cornerpoints:coordinates`. Для
  тестов запрос к Nominatim и пауза подменяются через `GEOCODE` / `DELAY`.
- `core.py` — градусы-минуты-секунды, поиск поля номера, `SubjectLookup`
  (Nominatim не чаще раза в секунду, кэш по координатам), МСК по коду и долготе.
- `msk.py` + `msk.json` — набор МСК и разбор ответа Nominatim, точная копия из
  `qgis-project-utm-crs` (правится там, сюда копируется байт в байт — как
  `altan_toolbar.py`). Своё здесь подставляется снаружи, файл не меняется:
  `core.py` задаёт `msk.USER_AGENT` (подстановка в `core.py`, а не в
  `plugin.py`, потому что алгоритм Processing — в том числе через `qgis_process` — идёт
  через `core.py`, а `plugin.py` при этом не загружается), а `table_algorithm.py`
  зовёт `msk.crs_for(item, register=False)`: МСК нужна только как цель
  пересчёта, писать её в «Пользовательские СК» профиля не надо.

## Грабли

- В выпущенной ведомости МО («Ведомость координат МО.xlsx», Дорохово) градусы у
  24 из 76 точек отличаются на ±0,01″ от посчитанных от вершин (МСК совпадает до
  0,000 м): её считали иначе, вероятно обратным пересчётом из МСК. Модуль прав;
  тест хранит два таких случая в `SAMPLE_OFF`.
- QGIS сам вызывает `initProcessing()` у модулей с `hasProcessingProvider=yes`, и
  `initGui()` вызывает его снова: второй провайдер отвергается как дубликат.
  Отсюда проверка в `initProcessing`.
- Окно Processing (`createAlgorithmDialog`) при закрытии удаляет себя само; а
  `execAlgorithmDialog` модальный. Сейчас кнопка окно не открывает.
- В тестах ссылку на провайдер держать в переменной: иначе Python удаляет его, и
  Processing пишет «Error creating algorithm from createInstance()».
- Параметр СК в `processing.run` не принимает строку PROJ — передавать
  `QgsCoordinateReferenceSystem`.
- Пустое поле в слое из Processing в 3.44 — `NULL`, а не `None`.
- Функцию нельзя класть атрибутом класса алгоритма (`self.geocode`) — станет
  методом; подмена — переменные модуля.
- Точность полей X/Y задаётся явно (`setPrecision`), иначе таблица показывает
  «418060,5».
- Флажок экспорта псевдонимов в русском QGIS не переведён: «Use aliases for exported name».
- Если провайдер с таким id уже зарегистрирован (вторая копия модуля в профиле, Plugin
  Reloader), QGIS отвергает второй и **удаляет объект**: ссылку держать нельзя, иначе
  `unload()` падает с «wrapped C/C++ object … has been deleted» и не убирает за собой.
  `addProvider()` возвращает bool — ссылку сохранять только при True.
- Поле из параметра `NUM_FIELD` может не существовать (сохранённая модель, пакетный запуск,
  `qgis_process` после смены слоя): без проверки наружу шёл `KeyError`. Проверяем через
  `source.fields().indexOf(...)` и пишем, какие поля в слое есть.
- Склонения — `core.plural(n, "точка", "точки", "точек")`: «1 строка», «3 строки», «11 строк».
- Предупреждение не должно прятать итог: сообщение собирается как «Готово: N строк» +
  предупреждения + подсказка про Excel.
- Больше `plugin.MANY_POINTS` (100) выделенных точек — сначала вопрос с оценкой времени и
  подсказкой про ручную МСК. Окно строит `many_points_box()` отдельно от показа, чтобы его
  можно было снять в `tests/ui_shots.py`.
- Длинные тексты ловит `ui_copy_audit.py` (признак ДЛИННОЕ): объяснение выносится в
  `setInformativeText`, а не в одну строку вопроса.
- В общих текстах `msk.py` названий кнопок быть не должно: было «нажмите «Определить
  заново»» — кнопка окна модуля «СК проекта», которой у нас нет. По замечанию отсюда
  оригинал исправлен (2026-10-01): `NO_ANSWER` — только «Нет связи с сервисом адресов
  OpenStreetMap.», что делать дальше, дописывает каждый модуль сам (у нас — алгоритм).
  Тест `test_offline_message_fits_this_module` не даёт чужой кнопке вернуться после
  очередного копирования общего файла.
- `msk.py` правится ТОЛЬКО в `qgis-project-utm-crs`. Нужна правка — делать её
  там, прогонять тесты того модуля и копировать файл во все копии
  (`corner_points_catalog`, `dxf_attr_export`), иначе `collision_check`
  ругается, а копии со временем разъезжаются и по поведению. Своё для модуля —
  подстановкой снаружи, в файл не вписывать.
